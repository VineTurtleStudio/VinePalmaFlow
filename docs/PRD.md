## 1. 项目概述

### 1.1 一句话描述
像 LocalSend 一样简单连接，像 Git 一样安全协作，像 Excel 一样灵活导出——但所有数据永远只在你自己的设备上。

### 1.2 核心价值主张
- **数据主权**: 零服务器、零账号、零上传，项目数据完全存储在本地文件系统。
- **格式自由**: 人读的 Markdown 与机器读的 Excel 之间双向互通，随时导出、随时导入。
- **轻量协作**: 同一局域网内设备通过 WiFi/蓝牙发现彼此，加密配对后即可同步项目，无需互联网。
- **双模式体验**: 普通用户用表单，专业用户写 YAML，同一套数据，两种操作界面。

### 1.3 目标用户
| 用户类型 | 场景 | 使用模式 |
|----------|------|----------|
| 自由职业者 | 管理多个客户项目，需要定期导出周报/进度表 | 普通模式 |
| 小型工作室（2-8人） | 局域网内协作，数据敏感不上云 | 普通模式 + 局域网同步 |
| 项目经理/技术负责人 | 自定义工作流、脚本化导出、版本回溯 | 专业模式 |
| 隐私敏感企业 | 内网环境，禁止外发数据 | 专业模式 + 自建模板 |

## 2. 双模式架构

### 2.1 普通模式（Standard Mode）

**设计理念**: 三步完成项目——选模板 → 填内容 → 导出。

| 维度 | 设计 |
|------|------|
| **界面** | 表单向导式，左侧项目树，右侧卡片/看板/列表三视图切换 |
| **字段** | 固定字段：项目名称、负责人、截止日期、状态（待办/进行中/已完成/已归档）、优先级（P0-P3）、标签、描述、附件路径 |
| **模板** | 内置 8 套预设模板，不可修改结构，只能填内容 |
| **导出** | 一键导出 `.md`（完整版）或 `.xlsx`（表格版），格式固定 |
| **共享** | 一键「发送给同事」，自动发现局域网设备，扫码/输 6 位码配对 |

**内置模板清单**:
1. 个人 OKR 追踪
2. 敏捷迭代看板（Sprint）
3. 内容发布排期
4. 客户跟进漏斗
5. 产品需求池
6. 读书笔记/知识管理
7. 家庭事务/装修计划
8. 空白项目

### 2.2 专业模式（Pro Mode）

**设计理念**: 数据完全透明，结构完全自由。

| 维度 | 设计 |
|------|------|
| **界面** | 双栏布局：左侧可编辑 YAML Front Matter + Markdown，右侧实时渲染预览 |
| **字段** | 完全自定义，支持嵌套对象、数组、自定义数据类型 |
| **模板** | 模板市场 + 自定义模板引擎（Handlebars/EJS），用户可编写 `.hbs` 模板文件 |
| **导出** | 支持自定义导出脚本，可导出任意格式（CSV/JSON/HTML/PDF） |
| **共享** | 细粒度控制：按标签/时间段/字段级选择同步内容，支持只读/读写/管理员三级权限 |
| **高级功能** | Git 集成钩子、版本历史（Time Capsule）、冲突三向合并、自定义脚本钩子 |

### 2.3 模式切换机制

```
首次启动
    └── 询问：「我是个人用户」→ 默认普通模式
        「我是团队管理员/开发者」→ 默认专业模式

运行时切换：顶部工具栏 🎛️ 图标
    ├── 普通模式 → 专业模式：显示底层 YAML + MD 源码
    └── 专业模式 → 普通模式：复杂结构折叠为「只读卡片」，显示关键字段摘要
```

**数据兼容性保证**:
- 普通模式创建的数据，专业模式下 100% 可解析，无信息丢失。
- 专业模式添加的自定义字段，普通模式下以「扩展属性」折叠面板展示，只读。
- 模式切换不触发数据转换，仅切换视图层。

### 3.3 数据导出

**导出引擎行为**:

| 导出格式 | 普通模式 | 专业模式 |
|----------|----------|----------|
| `.md` | 完整项目文件，含 YAML 元数据 | 同上，支持自定义模板 |
| `.xlsx` | 单 Sheet 表格，固定列宽，条件格式（红绿灯状态） | 支持多 Sheet、透视表、自定义公式 |
| `.csv` | 纯数据，无格式 | 支持自定义分隔符、编码 |
| `.json` | 不可用 | 完整结构化数据，用于 API/脚本 |
| `.pdf` | 不可用 | 基于 Markdown 渲染的打印友好版 |

**Excel 导出规范**:
- Sheet 1「项目概览」: 项目名称、负责人、起止日期、进度百分比、状态（条件格式：绿色=已完成，黄色=进行中，红色=延期）
- Sheet 2「任务明细」: 任务名称、负责人、截止日期、状态、优先级、备注
- Sheet 3「变更历史」: 仅专业模式导出，记录最近 30 天的字段修改记录

### 3.4 数据导入

**支持的导入源**:
1. **LocalFlow 原生 `.md`**: 完整解析 YAML + Markdown，反向生成项目结构
2. **Excel `.xlsx`**: 识别标准列头（名称/负责人/截止日期/状态/优先级），自动映射；非标准列头进入「扩展字段」
3. **Markdown 文件夹**: 批量导入一个文件夹内的所有 `.md` 文件，按文件名生成项目树
4. **模板导入**: 导入 `.localflow-template` 文件，自动注册为新模板

**导入冲突处理**:
- 同名项目 → 提示「覆盖 / 重命名 / 合并」
- 合并模式下：相同任务以最新修改时间为准，冲突字段高亮让用户选择

## 4. 局域网协作

### 4.1 设备发现（mDNS）

**技术实现**:
- 应用启动后，在局域网内通过 mDNS（Bonjour/Avahi）广播 `_localflow._tcp` 服务。
- 发现列表显示：设备名称 + 用户别名 + 设备类型图标（PC/手机/平板）。
- 发现范围：同一子网（可配置是否允许跨 VLAN）。

**用户界面**:
```
┌─────────────────────────────┐
│  🔍 发现附近的设备           │
├─────────────────────────────┤
│  💻 张三的 MacBook Pro      │
│     状态: 可连接             │
│  📱 李四的 iPhone           │
│     状态: 已配对 ✓          │
│  💻 王五的 ThinkPad         │
│     状态: 等待确认...        │
└─────────────────────────────┘
```

### 4.2 配对与密钥体系

**三层密钥架构**:

```
┌─────────────────────────────────────────────┐
│  Layer 1: 传输加密 (TLS 1.3)               │
│  ─────────────────────────────────────────  │
│  • 每次连接临时生成 X25519 密钥对           │
│  • ECDH 协商会话密钥 → AES-256-GCM         │
│  • 自签名证书，首次连接时指纹验证            │
├─────────────────────────────────────────────┤
│  Layer 2: 设备身份 (Ed25519)               │
│  ─────────────────────────────────────────  │
│  • 安装时生成永久 Ed25519 密钥对            │
│  • 公钥作为设备唯一身份标识                 │
│  • 信任设备列表存储在 ~/.localflow/trusted/ │
├─────────────────────────────────────────────┤
│  Layer 3: 项目级访问控制                    │
│  ─────────────────────────────────────────  │
│  • 每个项目可单独设置访问密码               │
│  • 即使设备已信任，无项目密码无法解密数据    │
│  • 支持只读 / 读写 / 管理员 三级权限        │
└─────────────────────────────────────────────┘
```

**配对流程**:
1. A 点击 B 的设备 → 发送连接请求（含 A 的公钥指纹）
2. B 弹窗：「张三的 MacBook Pro 请求连接」
3. A 和 B 的屏幕同时显示 **6 位数字配对码**（如 `482 913`）
4. 双方确认数字一致 → 交换公钥，写入信任列表
5. 可选：勾选「始终信任此设备」，下次自动连接

### 4.3 数据同步协议

**同步粒度**:
- **项目级同步**: 整个项目文件夹（推荐首次同步）
- **任务级同步**: 单条任务/子任务（推荐日常增量同步）
- **字段级同步**: 仅同步特定字段（专业模式高级功能）

**冲突解决（三向合并）**:
```
Base: 双方上次同步时的版本
Mine: 本地修改后的版本
Yours: 对方发送的版本

自动合并规则:
├── 不同字段修改 → 自动合并，无冲突
├── 同一字段，一方修改一方未改 → 采用修改方
├── 同一字段，双方都修改且相同 → 自动通过
└── 同一字段，双方都修改且不同 → 标记冲突，用户界面选择
```

**离线编辑支持**:
- 设备离线时正常编辑，本地记录修改时间戳。
- 恢复连接后自动检测差异，按「最后写入胜出」原则合并，冲突项进入「待解决」队列。

### 4.4 蓝牙备用通道

**触发条件**:
- WiFi 不可用（如户外、展会、无路由器环境）
- 用户手动选择「使用蓝牙传输」

**技术限制与处理**:
| 限制 | 处理方案 |
|------|----------|
| 距离短（10m 内） | 仅用于小文件/单任务同步，大项目提示「请连接 WiFi」 |
| 速度慢（BLE ~1Mbps） | 压缩数据（zstd），仅传输差异增量 |
| 配对麻烦 | 复用 WiFi 配对时的信任关系，蓝牙自动复用已信任设备 |
| 平台差异 | Windows 用 WinRT Bluetooth API，macOS 用 CoreBluetooth，Linux 用 BlueZ D-Bus |

## 5. 数据格式规范

### 5.1 Markdown 项目文件规范

**文件名**: `{项目英文标识}-{创建日期}.md` 或用户自定义中文名（内部仍以 `id` 字段为准）

**必需 Front Matter 字段**:
```yaml
---
id: "proj_<timestamp>_<random>"    # 全局唯一标识，不可修改
name: "项目名称"                    # 显示名称
status: active | archived | deleted # 项目生命周期
created_at: YYYY-MM-DD              # 创建日期
updated_at: YYYY-MM-DDTHH:MM:SSZ    # 最后修改时间（UTC）
version: 1                          # 数据格式版本号
---
```

**可选标准字段**:
- `owner`: 负责人
- `deadline`: 截止日期
- `priority`: P0 | P1 | P2 | P3
- `progress`: 0-100 整数
- `tags`: 字符串数组
- `parent_id`: 父项目 ID（支持项目嵌套）
- `sync_devices`: 已同步设备公钥指纹列表

**正文结构约定**:
```markdown
# {项目名称}          ← 一级标题，必须与 name 字段一致

## 项目目标          ← 二级标题，标准章节
## 关键里程碑        ← 建议使用任务列表 - [x] / - [ ]
## 风险与阻塞项
## 会议纪要
## 备注
```

## 6. 技术架构

### 6.1 技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| **桌面端框架** | Tauri (Rust + WebView) | 安装包 < 10MB，内存占用低，原生性能，安全沙箱 |
| **前端 UI** | React 18 + Tailwind CSS | 组件化、响应式、暗色模式支持 |
| **状态管理** | Zustand | 轻量，持久化到本地 Storage |
| **本地数据库** | SQLite (rusqlite) | 单文件、零配置、事务安全、跨平台 |
| **Markdown 解析** | pulldown-cmark (Rust) | 原生高性能，支持 CommonMark + GFM |
| **YAML 解析** | serde_yaml (Rust) | Rust 生态标准，类型安全 |
| **Excel 读写** | rust_xlsxwriter | 纯 Rust，无需 Node 依赖，功能完整 |
| **局域网发现** | mdns-rs | 跨平台 mDNS 服务发现与广播 |
| **数据传输** | tokio + tungstenite | 异步 WebSocket over TLS，支持二进制帧 |
| **加密** | ring | Rust 生态标准加密库，支持 AES-GCM / ECDH / Ed25519 |
| **数据压缩** | zstd-rs | 高压缩比、低延迟，适合蓝牙场景 |
| **蓝牙通信** | 平台原生插件 | Windows: WinRT, macOS: CoreBluetooth, Linux: BlueZ |

```
└──────────────┘ └─────────────┘ └─────────────┘
```

### 6.3 安全设计

**本地安全**:
- 项目文件默认存储在用户主目录 `~/LocalFlowWorkspace/`，权限设置为 `700`（仅所有者可读写）。
- 配置目录 `~/.localflow/` 存储密钥对和信任列表，权限 `600`。
- 应用内无「上传云端」按钮，所有网络请求仅限局域网 mDNS + WebSocket。

**传输安全**:
- 强制 TLS 1.3，使用自签名证书，证书指纹在首次配对时人工确认。
- 会话密钥每 24 小时或每次重新连接时轮换。
- 项目级密码使用 Argon2id 派生密钥，永不以明文存储。

## 9. 项目文件命名与组织规范

**工作区根目录**: `~/LocalFlowWorkspace/`（可配置）

**项目文件夹命名**:
```
{YYYY-MM-DD}_{项目英文标识或中文拼音}/
示例:
  2026-08-18_chanpin-chonggou-v2/
  2026-08-15_kehu-genjin-ABC-gongsi/
```

**自动生成的汇总文件**:
- `~/LocalFlowWorkspace/汇总视图.md` — 跨项目仪表盘，自动更新
- `~/LocalFlowWorkspace/.localflow/sync-status.json` — 各项目同步状态索引

**备份策略**:
- 每次导出 Excel 时，自动在 `.localflow/backups/` 生成时间戳备份
- 专业模式可配置 Git 自动提交钩子，每次保存 = 一次 commit
